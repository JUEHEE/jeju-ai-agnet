# 채팅 API 답변 문구·카드 형식

채팅 화면에 무엇을, 어떤 말투로 보여줄지 정한 명세이다. **표시 방식은 `config/ui.json`에서 바꾼다.** 배지 라벨·톤·색, 확률 표시 여부, 차트 카드 위치, 서비스 이름이 모두 이 파일에 있어서 코드를 고치지 않고 수정할 수 있다. 문장 틀은 `api/chat_cards.py`의 `TITLES`·`LEADS`에 있다.

**현재 결정 (2026-11-16, 모두 이후 수정 가능)**
| 항목 | 결정 | ui.json 키 |
|---|---|---|
| 배지 라벨·톤 색 | 초안 유지 (초록 #1F7A4D, 노랑 #8A5A00, 빨강 #B0352C, 회색 #4A4F4D) | `badges`, `tones` |
| 확률 숫자 | 숨기고 배지만 표시 (카드 데이터에는 남김) | `show_probability: false` |
| 판정 불가 라벨 | 출하 전 | `badges.no_data.label` |
| 차트 카드 | 채팅 안에 그림 | `chart_cards_in_chat: true` |
| 서비스 이름 | 미정 (임시 문구 사용) | `service_name: null`, `service_name_fallback` |

- 카드 생성 코드: `api/chat_cards.py`
- 질문 유형별 실제 응답 예시 15개: `docs/chat_examples/`. `python scripts/make_chat_examples.py`로 다시 만든다.

## 1. 원칙
1. **숫자는 카드에서만 나온다.** 가격·확률·기준 금액은 엔진 응답을 그대로 카드에 담는다. LLM 문장은 카드 값을 설명할 뿐 새 숫자를 만들지 않는다.
2. **말투는 해요체이다.** 짧고 쉬운 말로 쓴다. "손익분기점"보다 "지원 기준", "허브"보다 "가락시장"을 쓴다.
3. **확정 표현은 쓰지 않는다.** "지원돼요"가 아니라 "지원받을 가능성이 높아요"라고 쓴다. 지원 가능성 카드 뒤에는 고지 문구를 항상 붙인다.
4. **기준일을 항상 밝힌다.** 카드 부제에 "3월 14일 기준"을 넣는다.
5. **경고를 빠뜨리지 않는다.** 엔진의 `warnings`는 쉬운 문구로 바꿔 `notes`에 담는다. 바꿀 규칙이 없는 경고는 원문 그대로 둔다.
6. **LLM 없이도 답한다.** 카드마다 기본 안내 문구(`lead`)가 있어서, LLM이 없거나 실패하면 그 문구를 그대로 쓴다.

## 2. 요청과 응답
**요청** `POST /api/agent/chat`
```json
{"session_id": "abc", "message": "이번 달 지원받을 수 있나요?",
 "context": {"item": "양배추", "as_of": "2026-03-14", "mode": "replay"}}
```
`context`는 대시보드에서 지금 선택된 품목과 기준일이다. 질문에 품목이나 날짜가 없으면 이 값을 쓴다.

**응답**
```json
{"ok": true, "error": null, "session_id": "abc",
 "messages": [
   {"type": "text", "text": "가락시장 가격으로 예측해 봤어요. 지금 흐름이면 이달 평균이 기준보다 낮을 가능성이 커요."},
   {"type": "card", "card": { ...카드... }},
   {"type": "text", "style": "footnote", "text": "최종 지원 여부는 제주도 공고로 확정돼요. 예측은 판단을 돕는 참고 정보예요."}],
 "suggestions": ["왜 그렇게 봤어요?", "신청하려면 뭐가 필요해요?", "다른 품목은 어때요?"],
 "tool_calls": [{"name": "predict_support", "args": {"item": "양배추", "ym": "2026-03", "as_of": "2026-03-14", "mode": "replay"}}],
 "data_end": "2026-10-31", "model_version": "ewm3-2025-06"}
```
- `messages`는 순서대로 그린다(안내 문장 → 카드 → 고지).
- `suggestions`는 다음 질문 버튼이다.
- `tool_calls`는 근거 확인·디버깅용이다.

## 3. 카드 공통 필드
| 필드 | 뜻 |
|---|---|
| `type` | 카드 종류 (아래 표) |
| `badge` | `{code, label, tone}`. tone은 positive / caution / negative / neutral / info |
| `title`, `subtitle` | 큰 제목, 기준일·규격 |
| `metrics` / `facts` / `rows` / `steps` / `chart` | 카드 종류별 본문 |
| `notes` | 쉬운 말로 바꾼 주의 문구 |
| `actions` | 버튼. `{id, label, call: {tool, args, view}}`. 프론트가 LLM을 거치지 않고 바로 다음 API를 부를 수 있다 (`POST /api/tools/{tool}`) |
| `lead` | LLM이 없을 때 카드 위에 쓰는 안내 문장 |
| `source` | 근거: 엔진 함수, `data_end`, `model_version`, 기준일 |

## 4. 카드 종류
| type | 언제 (질문 예) | 엔진 함수 | 본문 |
|---|---|---|---|
| `support` | "이번 달 지원받을 수 있나요?" | `predict_support` | 예상·기준 금액, 확률, 80% 범위, 버튼(근거 보기·서류 준비·공고) |
| `announced` | "2월엔 지원됐어요?" (공고가 난 달) | `predict_support` (live) | 공식 월평균·기준, 지원 여부 |
| `basis` | "왜 그렇게 봤어요?" (근거 보기 버튼) | `predict_support`의 `basis` | 6단계 계산 과정 |
| `compare` | "다른 품목은 어때요?" | `predict_support("전체")` | 품목별 배지·확률·자세히 버튼 |
| `program` | "신청 기간이 언제예요?", "얼마 지원돼요?" | `get_config` (items, schedule) | 지원 내용·기간·방법·문의, 품목별 단가 |
| `docs` | "뭐가 더 필요해요?" | `check_docs` | 준비/누락 서류, 진행률 |
| `eligibility` | "우리 농협이 신청할 수 있나요?" | `check_eligibility` | 요건별 충족·미충족·확인 필요 |
| `market` | "요즘 시세 어때요?" | `get_market_data` (status, monthly) | 최근 가격·이달 평균, 월별 차트 데이터 |
| `volume` | "요즘 거래량은 어때요?" | `analyze_volume` | 최근 vs 이전 하루 평균, 변화율 |
| `season` | "언제 거래가 제일 많아요?" | `analyze_season` | 월별 거래량 차트 데이터, 상위 달 |
| `notice` | 범위 밖 질문 ("브로콜리도 돼요?") | — | 안내 문장, 지원 품목 보기 버튼 |

## 5. 지원 가능성 카드의 상태별 문구
| 엔진 값 | 배지 (code / label / tone) | 제목 | 안내 문장 (`lead`) |
|---|---|---|---|
| verdict 높음 | high / 지원 가능성 높음 / positive | {이번 달} {양배추는} 지원받을 가능성이 높아요 | 가락시장 가격으로 예측해 봤어요. 지금 흐름이면 이달 평균이 기준보다 낮을 가능성이 커요. |
| verdict 불확실 | uncertain / 아직 몰라요 / caution | … 아직 판단하기 어려워요 | … 기준선 근처라 남은 기간 가격에 따라 달라질 수 있어요. |
| verdict 낮음 | low / 지원 가능성 낮음 / negative | … 지원받을 가능성이 낮아요 | … 지금 가격이 기준보다 높아서 지원 가능성은 낮아 보여요. |
| status 판정 불가 | no_data / 출하 전 / neutral | … 지금은 판단할 수 없어요 | 지금은 판단할 근거가 부족해요. |
| 공고 확정, 지원 | supported / 지원됐어요 / positive | … 지원 대상이었어요 | 이미 공고가 난 달이라 실제 결과로 알려드릴게요. |
| 공고 확정, 미지원 | not_supported / 지원되지 않았어요 / negative | … 지원 대상이 아니었어요 | 위와 같음 |

- `{이번 달}`은 기준일 기준으로 "이번 달", "다음 달", "2월", "2025년 12월" 중 하나가 된다.
- 품목 뒤 조사(은/는)는 받침에 맞춰 자동으로 붙는다.
- 확률은 카드 데이터(`probability.value`)에는 있지만 `probability.show`가 false라 화면에는 배지만 보인다. 근거 보기에서도 확률 대신 판단 배지를 보여준다.

## 6. 경고 → 쉬운 문구
| 엔진 경고 (포함 문자열) | 화면 문구 |
|---|---|
| 손익분기점 공고 전 | 이번 시즌 기준 금액이 아직 발표되지 않아 지난 시즌 기준(2025/26)으로 계산했어요. |
| 관측 0일 | 아직 이달 거래가 시작되기 전이라, 월초 가격 흐름에 따라 크게 바뀔 수 있어요. |
| 가락시장 거래가 없음 | 최근 가락시장에서 거래된 기록이 없어 예측할 수 없어요. 보통 출하가 시작되면 판단할 수 있어요. |
| 환산 비율 근거가 1개월 | 이 품목은 비교할 공식 자료가 적어서 참고용으로만 봐 주세요. |
| 지원기간(11월~4월) 밖 | 물류비 지원기간(11월~이듬해 4월)이 아닌 달이에요. |
| 문서마다 값이 다른 | 신청 기간 등 일부 내용은 문서마다 달라서 최종 공고로 꼭 확인해 주세요. |
| 검증된 범위 밖 | 너무 먼 달이라 예측이 정확하지 않을 수 있어요. |
| 이미 공고된 달 | (표시 안 함. 카드 제목이 이미 설명함) |

`predict_support`가 내는 모든 경고에 규칙이 있는지는 테스트로 확인한다(`tests/test_chat_cards.py`).

## 7. 예시: 대시보드와 같은 장면 (3월 14일 기준 양배추)
```
가락시장 가격으로 예측해 봤어요. 지금 흐름이면 이달 평균이 기준보다 낮을 가능성이 커요.
┌─────────────────────────────────────────┐
│ [지원 가능성 높음]          3월 14일 기준 · 가락시장 8kg 망 │
│ 이번 달 양배추는 지원받을 가능성이 높아요                    │
│ 예상 5,182원 · 기준 6,116원                                  │
│ [근거 보기] [서류 준비] [공고]                               │
└─────────────────────────────────────────┘
최종 지원 여부는 제주도 공고로 확정돼요. 예측은 판단을 돕는 참고 정보예요.
```
"근거 보기"를 누르면 `basis` 카드가 나온다.
1. 지금까지 실제 평균 4,984원 (11일)
2. 남은 14거래일 예상 4,075원
3. 이달 평균 예상 4,475원
4. 공식 가격으로 환산 5,182원 (공식 가격이 보통 16% 높음)
5. 지원 기준 6,116원
6. 판단: 지원 가능성 높음 (확률 표시를 켜면 "기준 이하일 가능성 91%"가 추가된다)

## 8. 프론트와 정할 것
위 "현재 결정" 표로 정리했다. 바꿀 때는 `config/ui.json`만 고친다.

## 9. 아직 하지 않은 것
- `POST /api/agent/chat` 엔드포인트 자체. 질문 → 도구 선택(LLM 또는 규칙) → 카드 → 응답을 잇는 부분이고, 위 항목을 합의한 뒤 붙인다.
- LLM이 쓰는 안내 문장(`messages`의 첫 text)의 프롬프트. 카드 값만 근거로 쓰도록 규칙을 넣는다.
